# ---- ssm: CORRECTION (2026-07-13) — it IS installable, just not into THIS env ----
# The 2026-07-12 note ("CONFIRMED UNINSTALLABLE, do not retry") was too strong. The plain
# `pip install git+https://github.com/lindermanlab/ssm` failure is real, but it has two
# separable causes, and both are fixable:
#
#   1. "ModuleNotFoundError: No module named 'numpy'" — its legacy setup.py imports numpy at
#      build time without declaring it, so PEP-517 build ISOLATION starves it.
#      -> `--no-build-isolation` (with numpy already present).
#   2. "Microsoft Visual C++ 14.0 or greater is required" — ssm/cstats.pyx is a C++ extension
#      and this machine has no MSVC.  -> conda's mingw-w64 toolchain, NO admin install needed.
#      (Two sub-hurdles: gcc 5.3 needs -D__STDC_LIMIT_MACROS for pyport.h, and conda ships no
#      mingw import lib for python311.dll — generate one with gendef + dlltool.)
#
# Both are automated in `scripts/install_ssm_env.sh`. Verified 2026-07-13: builds, imports,
# and fits a Poisson rSLDS (Laplace-EM, recurrent transitions) on real IBL data.
#
# What remains TRUE: ssm must NOT go into `neurodatarehack`. It is a numpy-1.x package, and
# pip would downgrade numpy 2.3.5, taking pynapple / numba / pandas 3.0 with it. It lives in
# the separate `ndrh_ssm` env; the notebook calls it out-of-process via
# src/dynamics/rslds_ssm.py, so nothing from it is ever imported into this env.
#
